# Ruta C#

Este repositorio tiene como objetivo aprender el lenguaje y comprender la arquitectura de software.

El camino de este aprendizaje se divide en 4 pasos

----

## 1. Entorno de Desarrollo y Control de Versiones Real

#### Para este paso habra dos principales objetivos los cuales son:

- Crear un repositorio local, simular un flujo de trabajo creando tres ramas distintas, provocar un conflicto intencional y resolverlo mediante la terminal.
- Un script de C# muy básico ("Hola Mundo") subido a GitHub con un archivo ⁠.gitignore⁠ y un ⁠README.md⁠ perfectamente redactado.

### 2. El Corazón de C# (Tipos, Memoria y Control de Flujo)

#### Una vez teniendo los conocimientos podre empezar a manejar codigo puro, esto solo para obtener dos cosas: 

- Una calculadora de consola que maneje errores de entrada (ej. intentar dividir por cero o introducir letras en vez de números) sin que el programa colapse.
- El programa nunca se cierra inesperadamente; toda excepción está controlada y explicada al usuario.

### 3. El Arte del Debugging (El antídoto a la frustración)

#### Una vez entendido el codigo y el manejo de errores y mas cosas voy a poder aprender la forma correcta de encontar errores y que los causa, por eso en est punto tendre las siguientes metas:

- Tomar un código en C# proporcionado (con 3 bugs lógicos ocultos) y usar el debugger paso a paso para encontrarlos sin modificar el código hasta entender el fallo.
- Aplicar herramientas de debugging al proyecto de la calculadora para rastrear exactamente en qué línea de memoria falla una operación compleja.
-  Encontrar la raíz de un problema analizando el Call Stack de abajo hacia arriba.

### 4. Programación Orientada a Objetos (POO) y SOLID Básico

#### Una vez entienda como funciona git, el funcionamiento basico de C# y como enocntar errores y entenderlos podre crear un programa complejo donde refleje todos mis conocimientos y desarrolle nuevos a base de prueba y error, para ello tendre que generar lo siguiente:

- Modelar un sistema de línea de producción de fábrica usando clases e interfaces (ej. ⁠IdEmpleado⁠, ⁠MaquinaEnsamblaje⁠).
- Cada tarea es un objeto. El sistema debe guardar los datos en un archivo de texto plano (⁠.txt⁠ o ⁠.json⁠), el código debe estar dividido en clases con una sola responsabilidad, y se debe utilizar Git en cada paso.
- El proyecto funciona, el código es modular (no hay un solo archivo de 1000 líneas) y el manejo de errores es impecable.
